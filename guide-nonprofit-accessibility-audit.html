If your nonprofit serves the public, your website needs to be accessible. Not just because it's the right thing to do — because it's the law. The Americans with Disabilities Act (ADA) applies to websites, and nonprofit organizations are not exempt.

Why Accessibility Matters for Nonprofits

  • Legal compliance: ADA Title III covers nonprofit websites. Lawsuits are increasing.
  • Mission alignment: If you serve people with disabilities, your website should too.
  • Grant requirements: Many federal grants require WCAG 2.1 AA compliance.
  • SEO benefit: Accessible sites rank better in search engines.
  • Broader reach: 1 in 4 US adults has a disability. That's your audience.

What WCAG 2.1 AA Requires

WCAG 2.1 AA has four principles. Your website must be:

  1. Perceivable — content can be seen, heard, and perceived by all users
  2. Operable — navigation and forms work with keyboard, screen readers, and other assistive tech
  3. Understandable — content is clear, predictable, and forgiving of mistakes
  4. Robust — works with current and future assistive technologies

The 50-Point Audit Checklist

Our audit covers 50 checkpoints across 8 categories:

  • Color contrast and visual presentation
  • Keyboard navigation and focus management
  • Screen reader compatibility (ARIA, labels, landmarks)
  • Form accessibility (labels, error messages, validation)
  • Media alternatives (alt text, captions, transcripts)
  • Page structure and headings
  • Mobile and responsive accessibility
  • Performance and timing considerations

Free Tools to Start With

  • axe DevTools — browser extension, scans any page
  • WAVE — webaim.org/wave, free online checker
  • Lighthouse — built into Chrome DevTools
  • NVDA — free screen reader for testing
  • Keyboard-only testing — unplug your mouse and try to navigate

How to Run a Professional Audit

  1. Automated scan — run axe or WAVE on every page. This catches ~30% of issues.
  2. Manual keyboard test — navigate every page without a mouse. Can you reach all content?
  3. Screen reader test — use NVDA or VoiceOver to read through each page type.
  4. Color contrast check — verify all text meets 4.5:1 ratio (normal text) or 3:1 (large text).
  5. Document findings — create a report with severity levels and remediation recommendations.

Common Accessibility Issues on Nonprofit Websites

  1. Missing alt text on images — especially donor logos and event photos
  2. Low color contrast — gray text on light backgrounds is the #1 failure
  3. No keyboard navigation — dropdown menus and modals that trap keyboard users
  4. Unlabeled forms — "Name" as placeholder text instead of a proper label
  5. Missing headings — pages with no H1, or heading levels that skip (H1 → H4)
  6. No skip link — screen reader users must tab through entire nav on every page

How Long Does an Audit Take?

For a typical 20-page nonprofit website:

  • Automated scan: 15 minutes
  • Manual keyboard test: 1-2 hours
  • Screen reader test: 2-3 hours
  • Report writing: 1-2 hours
  • Total: 4-8 hours (less with a template)
